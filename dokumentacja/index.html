#2.0:. LEKTURA O "dot-gener"

Program "dot-gener" a w nim zawarty SilnikGrafu to generyczny nieświadomy o dziedzinie (rodzaje węzłów i lin, które deklaruje użytkownik) silnik sterowany schematem (typy węzłów i lin) który deklaruje użytkownik, z eksportem doDOT i SVG przez GraphViz.

PRZYKŁAD

const schemat = new SchematGrafu()
  .wezel("autor", {
    tag: "A",
    porty: ["dziela"],
    kategorie: { epoka: { pozytywizm: [], renesans: [] } },
    pola: { nazwisko: "" },
  })
  .wezel("ksiazka", {
    tag: "K",
    porty: ["autorzy"],
    kategorie: { rodzaj: { epika: ["powiesc", "nowela"] } },
    pola: { tytul: "" },
  })
  .lina("napisal", { tag: "N", od: { autor: ["dziela"] }, do: { ksiazka: ["autorzy"] } })
  .autoWezla("autor", { liczbaKsiazek: (a) => a.wyjscia("napisal").length })
  .szablonWezla("autor", (a) => ({ opis: [a.pola.nazwisko, `książek: ${a.auto.liczbaKsiazek}`] }));

const graf = new SilnikGrafu(schemat);
const prus = graf.dodajWezel("autor", { kategorie: { epoka: ["pozytywizm"] }, pola: { nazwisko: "Prus" } });
const lalka = graf.dodajWezel("ksiazka", { kategorie: { rodzaj: ["epika", "powiesc"] }, pola: { tytul: "Lalka" } });
graf.polacz("napisal", [prus, "dziela"], [lalka, "autorzy"]);
graf.doDot();

DECYZJE

  • Schemat jako builder. Funkcje pól automatycznych dostają w pełni otypowany widok sąsiadów. W jednym obiekcie konfiguracji typ zależałby od samego siebie, dlatego każde wywołanie buildera zwraca nowy typ.
    • Pole auto może więc sięgać tylko po pola auto zdefiniowane wcześniej, co wyklucza cykle już na poziomie typów.
    • Dla kodu w JS albo przy rzutowaniu jest dodatkowa kontrola w runtime (test 5).
  • Pola wpisywane. Wartości z pola są domyślne i z nich wynika typ: "" daje string, bo F nie ma modyfikatoraconst. Przy tworzeniu podajesz Partial tych pól. Unie literałów deklarujesz przez as.
  • Pola automatyczne są w osobnej przestrzeni auto, tylko do odczytu. Ich typ to ReturnType funkcji. Liczą się leniwie, a zapamiętany wynik jest unieważniany przy każdej zmianie grafu.
  • Identyfikator. Przechowywana jest tylko krotka [rodzaj, numer] z nadaj(). Tekst (K01) powstaje przy odczycie, bo szerokość z liczbaCyfr() rośnie: dziesiąty węzeł zamienia K1 w K01.
  • Domyślnie szerokość liczona jest osobno dla każdego rodzaju. Opcja { wyrownanie: "wspolne" } daje jedną szerokość (maksimum) dla całej puli.
  • Tag nie może kończyć się cyfrą. Inaczej A + 11 i A1 + 1 dałyby to samo A11. Kompilator zgłasza to czytelnym komunikatem, np. tag "K2" nie może kończyć się cyfrą, tak samo jak zajęty tag lub rodzaj.
  • DOT.
    • Porty to komórki tabeli HTML z atrybutem PORT. Kompas :e/:w (przy LR) albo :s/:n (przy TB) prowadzi linie do boku komórki.
    • Każda lina dostaje atrybut id="N01" z drugiej instancji SilnikUnikalnychKluczy, więc trafia on do SVG.
    • Własny label w szablonie wyłącza tabelę generowaną przez silnik.
  • Użyte elementy TypeScriptu i ES2025:
    • NoInfer w polacz, dzięki czemu rodzaj liny wynika tylko z pierwszego argumentu;
    • const type parameters, template literal types (komunikaty błędów, typ K${number}), infer w StanSchematu;
    • Exclude, Record, Readonly, Partial;
    • iterator helpers i Set.prototype.difference z ES2025;
    • blok static do dostępu schemat → silnik.
